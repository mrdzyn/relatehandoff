## Objective

Establish a local-first, self-controlled execution model where mandatory development CI and release-candidate verification do not depend on GitHub Actions or GitHub network access. GitHub Actions is retained solely as an optional supplementary convenience (`workflow_dispatch`), never a prerequisite or blocking gate for validating or approving a release.

Preserve full testing depth, artifact integrity (SHA-256 checksums), independent exact-HEAD audit, and explicit human merge and production release approvals.

## Acceptance criteria

1. **Local-First Release Verification:** An approved release candidate can be verified locally without invoking `gh`, GitHub APIs, or hosted GitHub Actions runners.
2. **Fail-Closed Execution:** Release verification fails closed (exit code non-zero) if working tree is unclean, any validation command fails, or any specified release artifact is missing or empty.
3. **Artifact Integrity:** The release verification process generates cryptographic SHA-256 hashes of release artifacts and produces durable sanitized evidence.
4. **Portability & Stack Independence:** The contract is documented as stack-agnostic (macOS, Linux, Windows), with native reference implementations in Python and shell wrappers for the master template, and guidance for non-Python stack-native entrypoints.
5. **Optional Supplementary Automation:** GitHub Actions `workflow_dispatch` is explicitly designated as optional supplementary convenience, not a release prerequisite.
6. **Greenfield & Brownfield Governance:** New greenfield projects inherit the local-first execution contract; mature brownfield projects preserve their existing release protections until individually reconciled and owner-approved.
7. **Human Approval & Audit:** Independent exact-HEAD audit and separate explicit human owner approvals for merge and production release remain strictly preserved.

## Validation Integrity Remediation (PR #26)

1. **P1-01 (Mandatory Self-Test Bypass Removal):** Removed `AG_ENTRYPOINTS_TEST_ACTIVE=1` top-level bypass in `scripts/validate.py`. 2. **P1-02 (Post-Development Git Integrity Recheck):** Added step 8 to `scripts/validate.py` re-checking `git rev-parse HEAD` and `git status --porcelain` after all development commands run. Unsupported/unproven isolation strictly reports `[NOT VERIFIED]`.
4. **P2-02 (Contract Identifier Evidence Confidentiality):** Enforced stable contract identifiers (`contract:categories.<key>`, `contract:release.command_<idx>`) and stable check names rather than user-defined command names across evidence records and error summaries in both entrypoints. Added regression test `test_contract_identifier_evidence_confidentiality` verifying secrets in names are never persisted.
5. **27-Test Entrypoints Suite:** Expanded `scripts/test_entrypoints.py` to 27 automated tests covering all previous 25 tests plus mandatory self-test bypass negative test, post-development git integrity, and contract identifier confidentiality.
6. **Custom Category Identifier Confidentiality:** Enforced safe validated categories allowlist (`SAFE_CATEGORIES`) in `scripts/validate.py`. Added negative test verifying embedded tokens in custom categories are neutralized.
7. **Platform-Aware CLI Launcher Tests:** Updated `test_cli_launchers()` in `scripts/test_entrypoints.py` to verify Python-native entrypoints on all platforms including Windows, accurately report POSIX wrapper coverage on native Windows without attempting direct POSIX execution, and preserve Linux/macOS wrapper execution tests.
