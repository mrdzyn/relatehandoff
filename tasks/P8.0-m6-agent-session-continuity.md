## Objective and non-goals

Introduce a deterministic, bounded, security-conscious **session-resumption contract** for agents starting with no previous chat history. The new agent must identify the actual active branch, commit, phase, task, handoff, next authorized action, unresolved decisions and evidence, and explicitly report uncertainty when sources cannot be read or verified.

This is **repository-driven context recovery**, not a claim that ChatGPT memory or cross-chat automatic tool execution is guaranteed. Agents without repository/connector permissions must identify the blocker and request a supported access path rather than infer state.

## Authoritative inputs / startup order

1. Read repository `AGENTS.md`.
2. Read `docs/STATUS.md` and `config/project-profile.json`.
3. Read only the active task/phase spec identified by STATUS.
4. Read only the exact active `## Handoff: <ID>` section in `docs/HANDOFFS.md`.
5. Inspect relevant code/test docs **only** for the identified next action.
6. Verify Git branch and full HEAD locally; when a PR or remote state matters, verify against live GitHub/approved Git remote when accessible. Treat stale file claims as claims until verified.

Do **not** routinely load the full HANDOFFS history or `docs/PROJECT-MEMORY.md`. Use memory only where historic rationale or durable decisions are specifically needed.

1. **Session Context Generator:** Created `scripts/session_context.py` implementing the read-only, offline-capable session-context generator per `docs/SESSION-CONTINUITY.md`. Fails closed (exit 1) on missing, stale, duplicated, or contradictory context.
