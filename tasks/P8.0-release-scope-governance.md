# P8.0 — Release Scope Preservation & Production Readiness Governance

- **Status:** Governance implementation complete; project-specific candidate adoption awaits owner selection.

## Objective

Prevent coding agents and technical auditors from silently removing, disabling, deferring, or replacing owner-approved production release features when external release gates are closed.

## Context

Following the squash-merges of P8.0 M5 (local-first CI and release validation) and M6 (session continuity and context recovery), a governance gap remains in AI-assisted delivery: when external release gates (such as staging test tracks, store accounts, hardware QA, production signing credentials, or live third-party gateways) are closed or unavailable, coding agents and technical auditors risk silently reducing scope, deleting feature code, substituting permanent mocks for live integrations, or creating unapproved deferrals to force a "passing" release candidate. This task establishes an immutable release scope governance contract and a reusable Release Scope Manifest, reconciles post-M6 main status, and enforces that closed gates block promotion rather than feature scope.
